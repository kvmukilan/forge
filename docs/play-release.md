# Shipping Forge to Google Play (TWA)

Forge ships to Android as a **Trusted Web Activity** (TWA): a native shell that
loads the live Vercel deployment in a full Chrome Custom Tab. Google OAuth and
Web Push work normally inside a TWA (unlike WebViews, where Google blocks OAuth).

## 0. Prerequisites (one-time)

- Production deployment on Vercel with a stable HTTPS domain (referred to as `<PROD>` below).
- Environment variables set in Vercel:
  - `AUTH_SECRET`, `DATABASE_URL` (Neon), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
  - `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (`npx web-push generate-vapid-keys`)
  - `CRON_SECRET` (any long random string)
  - `ASSETLINKS_FINGERPRINTS`, `TWA_PACKAGE_NAME` (filled in during step 4)
- [Play Console developer account](https://play.google.com/console) — one-time $25 fee.
  - **New personal accounts must run a closed test with ≥12 testers opted in for
    14 consecutive days before applying for production access.** Organization
    accounts are exempt. Start recruiting testers early.
- Java 17+ and Android SDK (Bubblewrap can install these itself).

## 1. Verify the PWA is Play-ready

```bash
# On the production URL:
npx lighthouse https://<PROD> --only-categories=pwa
```

Must pass installability: HTTPS, `manifest.webmanifest` (id, standalone,
192+512 icons, maskable icons), service worker (`/sw.js`, generated by serwist
at build time — note the SW is disabled in `next dev`, test on a build/deploy).

## 2. Generate the Android project

```bash
npm i -g @bubblewrap/cli
mkdir forge-twa && cd forge-twa
bubblewrap init --manifest https://<PROD>/manifest.webmanifest
```

Answers that matter:
- **Application ID**: `app.forge.twa` (or your own reverse-domain id — must match `TWA_PACKAGE_NAME`)
- **Display mode**: standalone; **Status bar / theme color**: `#000000`
- **Notification delegation: YES** (required for Web Push to display through the app)
- Let Bubblewrap create a signing key **or** reuse one; keep the keystore + passwords safe.
- Target SDK: accept the default (Bubblewrap tracks Play's requirement, API 35+ as of Aug 2025).

```bash
bubblewrap build   # produces app-release-bundle.aab + app-release-signed.apk
```

## 3. Create the Play listing

Play Console → Create app:
- Category: Health & Fitness (or Productivity)
- **Privacy policy URL**: `https://<PROD>/privacy`
- Upload `app-release-bundle.aab` to **Internal testing** first, then **Closed testing**.
- **Data safety form** (declare honestly):
  - Collects: Email address (account management, if Google sign-in), User IDs,
    "Health and fitness" / "Other user-generated content" (habits and completions).
  - All data encrypted in transit: yes. Data deletion: users can delete their
    account in-app (Settings → Delete account). Data sold: no. Data shared: no.
  - No ads, no third-party analytics.
- Content rating questionnaire: no objectionable content → Everyone.

## 4. Digital Asset Links (removes the browser URL bar)

1. Play Console → **Test and release → App integrity → App signing** → copy the
   **SHA-256 certificate fingerprint** of the *App signing key certificate*.
2. Also copy your *upload key* SHA-256 (from the same page, or
   `keytool -list -v -keystore android.keystore`) so locally-installed builds are trusted too.
3. Set on Vercel and redeploy:
   ```
   ASSETLINKS_FINGERPRINTS=<app-signing-sha256>,<upload-key-sha256>
   TWA_PACKAGE_NAME=app.forge.twa
   ```
4. Verify: `https://<PROD>/.well-known/assetlinks.json` returns the JSON, then
   install from the testing track — the app must open **full screen with no URL bar**.
   (Chrome caches verification; reinstall or wait if it doesn't apply immediately.)

## 5. Closed test → production

- Add ≥12 testers (email list or Google Group) on the Closed track.
- Testers must stay opted in for 14 consecutive days (personal accounts created
  after Nov 2023). Then apply for production access in Play Console.
- Before promoting: bump `versionCode`/`versionName` via `bubblewrap update`
  + `bubblewrap build` whenever the manifest/icons change. **Web updates need no
  new AAB** — the TWA always loads the live site; only shell changes need one.

## 6. Push notification cadence (Vercel plan note)

`vercel.json` schedules `/api/cron/push` **once daily at 13:40 UTC** because
Vercel Hobby only allows daily crons. The route is idempotent and
catch-up-safe: it sends any reminder whose local trigger time has passed and
that hasn't been sent today. **On Vercel Pro, change the schedule to
`40 * * * *` (hourly)** so reminders land near each user's chosen time and
evening streak-risk nudges fire in the right window.

## Troubleshooting

| Symptom | Cause |
|---|---|
| URL bar visible in the app | assetlinks 404/wrong fingerprint — recheck step 4 |
| Google sign-in shows 403 `disallowed_useragent` | You're in a WebView build, not a TWA — rebuild with Bubblewrap |
| Push notifications don't appear with app closed | Notification delegation off in `twa-manifest.json`, or Android 13 notification permission denied |
| `sw.js` 404 in dev | Expected — serwist only generates the SW for production builds |
